## Project Values

OpenCodeReview maintainers and contributors act consistently with these principles:

- **Open development:** Design discussion, issue tracking, and code review happen in public
- **Compatibility awareness:** CLI behavior and configuration should not change casually
- **Security first:** Changes affecting credentials or execution safety require extra scrutiny
- **Component ownership with cross-project accountability:** Maintainers own areas, cross-cutting changes require broader review
- **Documentation and implementation alignment:** Public contracts, code, examples, and docs should stay consistent

## Roles

- **Contributors:** Anyone who participates (issues, PRs, reviews, docs, tests)
- **Maintainers:** Trusted contributors with write access and review authority
- **Project Lead:** Provides overall direction and has final decision authority

## Decision Making

- **Day-to-day changes:** Normal PR workflow with maintainer review and rough consensus
- **Significant changes:** Broader review, proposed via GitHub Issue before implementation
- **Consensus:** Lazy consensus preferred; Project Lead decides if consensus cannot be reached
